# P7 — Início e caminhos de conserto

Escopo: P0 da auditoria e P1 de pausa/pendências, sem aplicar a direção visual nova. Worktree própria a partir de origin/develop com o PR #1 incorporado.

- `/` e rota desconhecida abrem Início; login também termina em `/`. Os hashes antigos continuam aceitos. Início passa a ser a primeira opção da navegação existente.
- Semáforo em bloco dominante, com frase de estado e verde/amarelo/vermelho, sem emoji. Título de 28 px versus 16,8 px nos cards. Sem redesenho da navegação. Após revisão UX/TL, pausa usa fundo neutro e o amarelo usa --warning: #fde68a, autorizado pelo TL.
- Fonte perdida e remoção de grupo-fonte levam a `/fontes`, provisória com instruções. Grupo de destino, número bloqueado, falhas e tipos novos levam a instruções em `/ajuda`. Bloqueio de número não leva a repareamento. Teste percorre 13 combinações de tipos/fontes e confere a rota resolvida.
- Pausar exige “Pausar todos os envios?”. Cancelar não chama a API; retomar não pede confirmação.
- Pendências vêm de `GET /pendencias` no carregamento e atualização. A fixture entrega dados diferentes de `/operacao` para detectar derivação indevida.
- Navegação HTML desconhecida recebe o shell do PWA; endpoints registrados continuam exigindo sessão mesmo com Accept HTML. Arquivo JS ausente não recebe o shell.
- Operations usa `feedback-erro` e mantém `role="alert"`, conforme alinhamento com J9/PR #3. Essa classe depende do CSS do PR #3; incorporar J9 antes do merge final.

Testes: 135 aprovados, um ignorado por ausência de TEST_DATABASE_URL (Postgres TCP). API 32, PWA 11, core 57, Amazon 14 e WhatsApp 21. Build escreveu dist; testes usaram dados sintéticos. Captura e logs locais foram produzidos para revisão. Sem alteração de schema ou dados persistentes.
